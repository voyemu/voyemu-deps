# Профили и машины

Профиль описывает одну прошивку, машина — то, что из него делает подготовка. Подготовка читает профиль, запуск читает только машину. Причины — в записи [профили как источники, машины как результаты](../why/profiles-machines.ru.md).

## Профиль

Профиль — авторский каталог `profiles/<profile>/`. Имя кодирует линейку автомобиля, поколение Android, язык прошивки, её дату и версию, например `free-09-chinese-20260106-6.0.3`. `voyemu list` выводит известные идентификаторы профилей; у [опубликованных профилей](../profiles/index.ru.md) есть свои страницы.

| Файл или каталог | Содержимое |
| --- | --- |
| `profile.json` | Пин системного образа Android, настройки эмулятора, экраны, оригиналы с SHA-256, рецепты, устанавливаемые файлы, настройка гостя и проверки |
| `capture.json` | Какие штатные файлы импорт берёт из физического автомобиля |
| `profile-qnx.json` | Штатные образы QNX, аппаратный адаптер, настройки хранилища и оригиналы, взятые из другого профиля; есть только в профилях с приборкой |
| `components/` | [Компоненты](components.ru.md) профиля |
| `patches/` | Шаги рецептов, на которые ссылается `profile.json` |
| `files/` | Небольшие собственные файлы, которые подготовка устанавливает в гостя |

Поле `status` в `profile.json` равно `ready`, когда мультимедиа поддерживается, и `incomplete`, пока оригиналы профиля ещё собираются: тогда `fetch PROFILE --source=adb --serial SERIAL` читает их по `capture.json`. Поле `status` в `profile-qnx.json` равно `incomplete`, пока приборка экспериментальная. Поддержка каждого опубликованного профиля указана в разделе [профили](../profiles/index.ru.md).

Поле `title` в `profile.json` называет профиль в тексте для людей, например `Free 7.3.1`. Поле `platform` равно `qinggan09` или `qinggan11` для поколения Android 9 или Android 11 [платформы Free/Dreamer](../GLOSSARY.ru.md) либо `passion` для Passion. Поле `board` называет плату мультимедиа: `8155` для Qualcomm SA8155 или `nxp` для NXP i.MX 8QuadMax. Опубликованный профиль без этих полей или с другим значением Voyemu отклоняет.

Общие части лежат вне профилей: `profiles/common/` содержит общие компоненты, шрифты, значки и графику руля, а `profiles/common-qinggan-09/` и `profiles/common-qinggan-11/` — рецепты ядра разработки для каждого поколения Android, `profiles/common-passion/` — вариант рецепта `qinggan-11` для Passion.

Оригиналы в репозиторий не попадают. Пользователь импортирует их в `.local/profiles/<profile>/`, а профиль хранит только их имена, размеры и SHA-256.

## Машина

Машина — подготовленный каталог `machines/<name>/`. `voyemu build PROFILE` по умолчанию создаёт `machines/PROFILE`, а `build PROFILE machines/NAME` задаёт другое имя. Каталог назначения должен быть новым и лежать прямо в `machines/` установки.

| Путь | Содержимое |
| --- | --- |
| `runtime.json` | Манифест машины: идентичность профиля, образы гостей, загрузочные файлы и ресурсы с размерами и SHA-256 |
| `profile.json` | Встроенная копия авторского профиля |
| `android/` | Системный образ и образ раздела `vendor` Android, ядро, записываемые диски пользователя и кеша, установленные пакеты |
| `qnx/` | Загрузочные образы QNX и записываемый диск QNX; только если приборка подготовлена |
| `ui/` | Логотип Voyemu, штатные загрузочные анимации в `ui/startup/`, графика руля и маршруты кнопок |

`runtime.json` появляется последним, после проверочной загрузки гостей, поэтому каталог без него машиной не считается. Команды жизненного цикла выбирают машину по пути, относительному или абсолютному, в том числе вне корня установки, и узнают профиль из `runtime.json`.

## Копирование и перенос машины

В машине есть всё, что запуску нужно из профиля, поэтому она работает без `profiles/` и переносится одним каталогом. Записываемые диски внутри машины, в том числе слои QCOW2 Android, хранят установленные приложения, файлы и настройки, поэтому после чистой остановки копируется или архивируется весь каталог машины. Состояние сеанса лежит отдельно, в `.local/machines/<name>/`, и создаётся заново, если его нет; см. [корни `.local`](local-roots.ru.md).

Для работы машине нужны установленные инструменты хоста. Для запуска приборки нужна ещё привязка QEMU и ANGLE в `.local/toolchains/installed.json`: её записывает подготовка машины на своём хосте. `deps` устанавливает движок, а `start` привязку не создаёт, поэтому на хосте без привязки машина запускается с `--cluster=off`. `voyemu check MACHINE_PATH` проверяет сохранённые файлы и настройку запуска, не запуская гостей.

Независимым копиям нужны разные имена каталогов: состояние сеанса привязано к имени каталога машины, а у машины не больше одного сеанса.

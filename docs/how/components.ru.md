# Компоненты и рецепты

Профиль меняет штатную прошивку только объявленными рецептами и компонентами. Подготовка применяет их к точным исходным байтам и останавливается при любом расхождении, поэтому машина одинакова, где бы её ни подготовили. APK и DEX обрабатываются на Java, и JDK пользователя для этого не нужен, см. [подготовку на Java](../why/java-preparation.ru.md).

## Компоненты

Компонент — каталог `components/<name>/` с `component.json` внутри профиля или в `profiles/common/`. `profile.json` перечисляет используемые компоненты в `components` парами «имя — путь». Поле `type` в `component.json` указывает, что строит подготовка:

| Тип | Результат |
| --- | --- |
| `apk` | Приложение Android, собранное из исходников и подписанное объявленным ключом |
| `jar` | Библиотека Java для фреймворка гостя |
| `native` | Нативный исполняемый файл или библиотека гостя, собранные в CI закреплённым NDK и скачиваемые по пину |
| `native-library-archive` | Нативные библиотеки из закреплённого архива |

Сторонние исходники и архивы внутри компонента закреплены по URL и SHA-256 в его `component.json`, см. [пины](../why/pins.ru.md).

Несколько профилей могут собирать один компонент из общих исходников. Поле `sourceFiles` в их `component.json` перечисляет файлы компонента из `profiles/common/`, которые берёт сборка, включая файлы варианта для поколения прошивки профиля. Поле `sourceEdits` называет точные текстовые правки, которые приспосабливают общие исходники к прошивке профиля, например убирают API, которого эта прошивка не объявляет. Если исходный текст правки не найден, подготовка останавливается. Компонент `native` тоже берёт общие исходники C через `sourceFiles`, но без правок.

Компонент `native`, результат которого уже публикует другой профиль, называет этот пин в поле `pin` в виде `<profile>/<component>`. Подготовка скачивает опубликованный файл, а собственного файла для этого компонента профиль не публикует.

## Рецепты и guard

Рецепт — запись в `patches` файла `profile.json`. Он называет вход, например `original:Launcher` для штатного APK, используемые компоненты, список шагов и ключ подписи. Шаг — JSON-файл в `patches/` со списком операций: правки строк в декомпилированных исходниках, добавление DEX, удаление записей, объявление библиотек и слияние классов.

Guard — точные исходные байты: каждый оригинал закреплён SHA-256 в `profile.json`, а правка строк закрепляет ещё и SHA-256 своего результата. Любое расхождение останавливает подготовку раньше, чем изменённый файл попадёт в машину. Штатные имена пакетов не меняются; собственные компоненты Android и классы Java подготовки используют `com.voyemu.*`.

## Установка и настройка гостя

После рецептов настройку гостя завершают три раздела `profile.json`:

- `install` кладёт артефакты в образ гостя: оригиналы, изменённые файлы, компоненты и закреплённые записи `files/`, у каждого — целевой путь и права.
- `configure` задаёт свойства загрузки, настройки Android, домашнюю активность и службы, которые запускаются вместе с гостем.
- `verify` перечисляет службы, активности и приоритеты домашнего экрана, которые проверочная загрузка должна увидеть до записи `runtime.json`.

## Ядра разработки

Часть профилей заменяет ядро эмулятора ядром разработки для своего поколения Android. Рецепт лежит в `profiles/common-qinggan-09/components/kernel/` или `profiles/common-qinggan-11/components/kernel/`, а Passion использует вариант в `profiles/common-passion/components/kernel/` — рецепт `qinggan-11` с поддержкой VLAN 802.1Q; рабочий процесс `kernels` собирает его из закреплённых исходников и публикует образ как ресурс релиза `kernel-<name>-<sha8>`. Профиль закрепляет этот ресурс в `android.development_kernel` по URL и SHA-256, а `fetch` скачивает его в `.local/toolchains/`. См. [CI](../dev/ci.ru.md); причины — в записи [ядра разработки, собранные в CI](../why/guest-kernels.ru.md).

# Глоссарий

Единый справочник терминов для документации, README, CHANGELOG, SECURITY и CONTRIBUTING Voyemu; пара к [GLOSSARY.md](GLOSSARY.md), обе версии правятся по смыслу. Каноническая форма — в левой колонке, варианты справа не используются. В коде, опциях CLI и именах API остаются идентификаторы в моноширинном начертании; в прозе — русский термин. При первом упоминании переведённого термина рядом стоит английский оригинал.

`java src/dev/checks/CheckDocs.java` отклоняет каждый вариант из колонки «Не использовать» вне моноширинных фрагментов и блоков кода. Вариант со сноской корректен в контексте, который называет сноска; это проверяет ревью.

## Сеансы и API

| Термин | Значение | Не использовать |
| --- | --- | --- |
| сеанс | Один запуск гостей машины под управлением супервизора (session); у машины не больше одного сеанса; имена API `session.*` не меняются | сессия |
| супервизор | Процесс хоста, который владеет сеансом и процессами гостей | демон |
| владение | Право изменять сеанс, подтверждённое `ownership_id`; `session.attach` даёт доступ только на чтение | — |
| поколение | Номер одного запуска гостя; перезагрузка создаёт новое поколение (`qnx_generation`, `android_generation`) | — |
| Voyemu API | Публичный интерфейс для скриптов: `voyemu test` читает один JSON-запрос со `schema: 1` и пишет один JSON-ответ; операции перечисляет `info` | JSON API |
| операция | Один запрос Voyemu API с именем в поле `op`; его выполняет `voyemu test` | команда⁵ |
| квитанция | Сохранённый результат зарегистрированной операции; повторный запрос получает его снова | — |
| исход | Классификация результата операции: `completed`, `not_started` или `unknown` | — |
| роль экрана | `primary`, `secondary`, `cluster`, `rear` (экран заднего ряда Free 6.11.1 и 7.3.1) или `hud` (второй экран QNX у Passion, 1280×720); не номер дисплея эмулятора и не ID дисплея гостя | слот экрана, третий экран |
| окно экранов | Второе окно хоста с остальными экранами автомобиля; его открывает переключатель у руля | дополнительное окно |
| межгостевая связь | QNET и ретранслятор Ethernet между гостями Android и QNX | — |
| `flush` | Запрос, который хост отправляет QNX через почтовый ящик межгостевой связи: прежде чем хост приостановит или остановит QNX, гость синхронизирует и перемонтирует хранилище и отвечает ACK со статусом | — |
| модель автомобиля | Состояние синтетического автомобиля на хосте, которое меняют `patch` и `vehicle.set` | — |
| поле | Одно именованное значение модели автомобиля | — |
| модель CAN | Синтетическая шина CAN гостя мультимедиа; API `vehicle.can.*` | — |
| поле MCU | Одно значение штатного протокола MCU, которое поддерживает адаптер приборки | — |
| канал данных приборки | Постоянное соединение мультимедиа с `ivcd` приборки, по которому в штатных кадрах IVC идут название трека, звонок и подсказки навигации; API `cluster.ipk.history` | канал синхронизации IPK, канал IPK |
| наблюдатель UI | Компонент Android, который читает дерево UI для `session.ui` | — |
| провайдер | Внешний процесс, зарегистрированный как источник наблюдений; поставщик контента Android — отдельный термин | — |
| снимок экрана | Изображение экранов, которое снимает `session.screenshot` (screenshot) | скриншот |
| кадр | Одно изображение, которое выводит гость; кадры QNX также доступны по gRPC | — |
| файл обнаружения | `qnx-frame-grpc.json` с адресом, портом и токеном конечной точки gRPC кадров QNX для текущего поколения приборки (discovery file) | файл discovery |
| холодный старт | Запуск гостя без восстановления RAM | холодная загрузка, холодный запуск |
| тёплая перезагрузка | Перезагрузка гостя с сохранением сеанса и владения; `mode: warm` в `multimedia.reboot` | мягкая перезагрузка |
| снимок RAM | Сохранённая RAM гостя, которую запуск может восстановить вместо холодного старта (checkpoint). Для Android это RAM эмулятора, которую супервизор сохраняет при остановке сеанса. Для QNX это RAM вместе с состоянием QEMU; её восстанавливает только запуск без межгостевой связи и постоянного хранилища, поэтому подготовленные машины запускают QNX холодным стартом, а событие лога `checkpoint.selected` записывает выбор и его причину | чекпойнт, чекпоинт |
| приёмка | Проверка сценария гостя на запущенной машине; тесты хоста её не заменяют | — |
| скрипт запуска QNX | Скрипт оболочки `qnx-runtime.sh`, который подготовка устанавливает в гостя QNX; он отправляет сигнал готовности анимации и просит сеанс включить зажигание | — |

## Канцелярит — не использовать

Отглагольное существительное с «осуществляет», «производит» или «выполняет» заменяется одним точным глаголом.

| Не использовать | Писать |
| --- | --- |
| осуществляет запись | записывает |
| производит проверку | проверяет |
| выполняет подготовку | подготавливает |
| осуществляет запуск | запускает |

## Склейки — не сращивать латиницу с кириллицей

Английское слово не сращивается с русским через дефис. Допустимы устоявшиеся аббревиатуры в первой части: USB-музыка, JSON-ответ. Клиент и сервер протокола называются с аббревиатурой после слова: клиент ADB, сервер ADB.

| Не использовать | Писать |
| --- | --- |
| dev-режим | режим разработки |
| UI-компоненты | компоненты интерфейса |
| host-тесты | тесты хоста |
| guest-процесс | процесс гостя |

## Русская проза

Принцип: от сути к детали, действие вместо штампа.

1. Сначала идея, потом механизм.
2. Точные глаголы вместо общих слов и штампов; фраза читается как действие («машина запускается без авторского профиля», не «обеспечивается независимость запуска»).
3. Русское слово вместо кальки, глагол вместо отглагольного существительного.
4. Разбивать тяжёлые конструкции: длинную цепочку причастных оборотов — на короткие предложения, тире и вставки.
5. Не пересказывать: вторая мысль — новый факт, а не парафраз первой.
6. Главное — в конце предложения: новое и важное ставить последним.
7. Конец предложения — короткий; длинное перечисление выносить в список или отдельное предложение.
8. Запятая перед тире — только когда она закрывает оборот или придаточное («Всё, что нужно, — здесь»); в остальных случаях один знак.
9. Одна мысль — одно предложение; один абзац — одна строка.
10. Писать факты, которые нужны пользователю; без восторгов, догадок об аудитории и воды.
11. Называть возможность по результату для пользователя (что эмулируется, что он может сделать), а не по деталям реализации: числу окон, внутренним именам платформ.
12. Простой язык: привычное слово вместо термина, если термин ничего не добавляет.
13. Не обращаться к читателю: ни «ты», ни «вы». Факты и поведение описываются в третьем лице — Voyemu, команда, разработчик, профиль делают X. Порядок действий — нумерованные шаги или предложения в инфинитиве («Изменить рецепт, воспроизвести образ, внести пин»); тяжёлый пассив не нужен.
14. Числа из пяти и более цифр делятся в прозе на разряды неразрывным пробелом (65 536 байт); значения и границы полей и параметров из кода пишутся как в коде (`timeout_ms` от 1 до 10000, 4294967295).
15. Профиль называется моделью и версией прошивки, как их видит пользователь: Free 6.0.3, Free 6.11.1 и 7.3.1, Free NXP RC45, Passion; внутренние сокращения вроде A9 и A11 не используются. Где важно поколение платформы, пишется Android 9 или Android 11; идентификаторы вроде `qinggan09` остаются в моноширинных фрагментах.

## Примечания к исключениям

¹ Канонический термин — «лаунчер»; «исполняемый файл» корректен, когда важен сам файл. Лаунчер Android — приложение домашнего экрана гостя.

² «Сервер» корректен для сетевой службы: сервер ADB, конечная точка gRPC кадров QNX.

³ «Модуль» корректен для модулей ядра и модулей Java.

⁴ «Собрать» и «сборка» относятся к команде CLI `build` и к компиляции Voyemu из исходников; действие `build PROFILE` называется «подготовить».

⁵ «Команда» корректна для команды CLI, например `start` или `test`.

⁶ «Процесс» корректен для процесса операционной системы, например процесса супервизора; процесс GitHub Actions называется «рабочий процесс».

⁷ «Ставить» в значении «помещать» или «задавать значение» корректно: модель ставит `ign` в 0.

⁸ «Сценарий» корректен для сценария автомобиля или гостя, например синтетического телефонного сценария.

# Пины

У каждого внешнего входа есть точная версия, URL и SHA-256, записанные в одном из файлов ниже. Инструменты сверяют SHA-256 до использования файла, а расхождение останавливает шаг. Правило и его причины — в записи [пины внешних входов](../why/pins.ru.md).

## Где лежат пины

| Файл | Что закрепляет |
| --- | --- |
| `src/app/toolchain.json` | Части Android SDK (command-line tools, Platform Tools, Emulator, Build Tools) и файлы их архивов, которые Voyemu проверяет или запускает напрямую, например Emulator, его e2fsck, его библиотеки ANGLE и SwiftShader и `android.jar` из архива платформы, NDK со списком файлов архива каждого хоста, CMake и Ninja из SDK, JDK, e2fsprogs (архив релиза и собранные в CI помощники каждого хоста), собранные в CI гостевые двоичные файлы QNX каждого аппаратного адаптера с начальным нативным состоянием, с которым они собраны, собранные в CI нативные компоненты Android каждого профиля, собранный в CI гостевой код Java профилей, среда Java подготовки (её модули, jmods Temurin каждого хоста и собранная в CI среда каждого хоста), собранный в CI помощник Java подготовки, инструменты сборки каждого хоста (Zig, CMake, Ninja, JDK), clang-format, clang-tidy, Uncrustify (архив релиза и собранный в CI исполняемый файл каждого хоста), google-java-format, Checkstyle, Error Prone, apktool и smali, исходники сборки ядра разработки и адрес релизов с образами ядер |
| `src/app/qnx-host.json` | Движок QEMU для QNX для каждого хоста с его патчами и распаковщиком, а в `prebuilt` — собранный в CI движок каждого хоста |
| `src/app/dependencies.lock.json` | Сторонние нативные исходники, которые компилируются в Voyemu, с SHA-256 каждого файла |
| `src/prepare/toolchain.json` и `src/prepare/libraries.json` | Библиотеки Java и JAR-файлы инструментов сборки Android, которые использует подготовка |
| `component.json` | Сторонние исходники одного компонента: SDL3 и заголовки X11 и Wayland для его драйверов Linux в `src/app/platform/`, библиотеки HTTP/2 в `src/app/api/`, гостевые компоненты в профилях |
| `profile.json` | Системный образ Android с пинами его содержимого в `android.clean_base` (список файлов распакованного архива, файлы загрузки, образы system и vendor, логические разделы образа API 30 и отдельные файлы гостя), образ ядра разработки, оригиналы и их извлечение из архивов прошивки |
| `profile-qnx.json` | Штатные образы QNX профиля |

Оригиналы закреплены только именем, размером и SHA-256; их байты в репозиторий не попадают. Файлы самого репозитория никогда не закрепляются. Код читает каждый пин из его файла и нигде его не повторяет.

Каталог полей Passion `src/app/core/passion_catalog.inc` порождается из оригинала: `src/app/core/generator/GeneratePassionCatalog.java` читает таблицу сервисов SOME/IP `H53_SOMEIP_ServiceTable_V6.0.0_OIB_8155_QNX_20240103-142433.json`, извлечённую из `system_la.img` профиля Passion, проверяет её SHA-256, который служит и `map_sha256` состояния Passion, и записывает каталог; команды даёт его Javadoc.

Системные библиотеки, которые хост загружает при запуске, не скачиваются, и пинов у них нет: на Linux это libcurl и libcrypto из OpenSSL 3, загружаемые по стабильным именам `libcurl.so.4` и `libcrypto.so.3`.

## Обновление зависимости

1. Брать последний релиз зависимости, если записанная причина не требует другой версии.
2. Менять версию, URL и SHA-256 вместе, в том единственном файле, который их закрепляет.
3. В том же изменении обновить файлы, которые используют пин, например файл набора инструментов или рецепт.
4. Собрать и запустить затронутые [тесты](tests.ru.md) и [проверки](checks.ru.md).

Рабочие процессы CI устанавливают инструменты по тем же пинам, поэтому изменение пина действует в [CI](ci.ru.md) без правки рабочего процесса.

Собранные в CI исполняемые файлы Linux — помощники образов e2fsprogs и Uncrustify — берут базу glibc лаунчера из `src/dev/toolchains/zig-linux-x64.cmake`. Смена этой базы, как и смена пина Zig, меняет их байты: их нужно пересобрать и обновить их пины и теги релизов, как описано в [CI](ci.ru.md).

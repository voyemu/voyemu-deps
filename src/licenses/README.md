# Embedded license catalogue

The native catalogue is generated by `src/app/licenses.cmake` and compiled into the single host executable through `voyemu_cluster_ui`; viewing a notice reads no runtime files and performs no network requests.

Voyemu uses the repository `LICENSE` (MIT, Voyemu Team 2026). nlohmann/json uses the complete `nlohmann-json.txt`, byte-identical to JSON 3.12.0 `LICENSE.MIT`; Dear ImGui uses `ImGui.txt`, byte-identical to ImGui 1.92.9b `LICENSE.txt`. Both copies are checked against the SHA256 values in `src/app/dependencies.lock.json` during CMake generation.

The Dear ImGui source target compiles `imgui_draw.cpp` and `imgui_widgets.cpp`, which incorporate `imstb_rectpack.h`, `imstb_truetype.h` and `imstb_textedit.h`. `stb.txt` copies their shared complete dual-license block (Sean Barrett 2017) from the dependency-pinned `imstb_rectpack.h`; these headers and their hashes are listed in the same lock file. The native submenu exposes stb separately.

SDL3 is compiled statically from the release pinned in `src/app/platform/component.json`. Its entry embeds `SDL3.txt`, byte-identical to that release's `LICENSE.txt`, followed by `SDL3-bundled.txt` with the notices of the third-party code that SDL3 compiles on every host: yuv2rgb (BSD-3-Clause, Adrien Descamps 2016, its complete `LICENSE`), the fdlibm math functions of `src/libm` (Sun Microsystems 1993), the sort of `SDL_qsort.c` (Gareth McCaughan), the surface rotation of `SDL_rotate.c` from SDL_gfx (Andreas Schiffler) and the controller type list of `controller_type.c` (Valve). On Linux the entry also embeds `SDL3-xdg-user-dirs.txt`, the MIT notice of the xdg-user-dirs lookup (Red Hat 2007) in the unix filesystem backend of SDL3, and `SDL3-x11-wayland.txt` with the notices of what its X11 and Wayland drivers compile: the EDID parser (Red Hat 2007), the XSETTINGS client (Red Hat 2001, 2007, Igalia 2024) and its settings glue (Igalia 2024), the keysym table `imKStoUCS.c` (Jamey Sharp, Josh Triplett, Red Hat, Oracle) and the copyright blocks of the Wayland protocol files whose code SDL3 generates with `wayland-scanner`. The X11, Wayland, xkbcommon and libdecor headers pinned under `window_linux` declare the interfaces of the system libraries that SDL3 loads at run time and bring no code of their own. The window builds SDL3 without HIDAPI and the other subsystems it does not use, so their bundled code is not compiled; the public-domain code SDL3 compiles, such as dlmalloc, the CRC and murmur3 hashes and `SDL_strtokr.c`, needs no notice, and the stb_image of `SDL_stb.c` is covered by `stb.txt`.

Preparation decodes the OEM startup videos with the host's own H.264 decoder: VideoToolbox on macOS, Media Foundation on Windows and the system libavcodec on Linux. Voyemu neither embeds nor ships a video codec, so the catalogue has no codec entry.

Every host embeds the nghttp2 notice for the pinned static HTTP/2 frame server. Windows and Linux also embed the curl notice for their static plain-HTTP SDK media client; HTTPS downloads on Linux load the system libcurl and OpenSSL 3, which are not embedded. Both notices come from `src/app/api/licenses/*-COPYING`. The Windows curl build provides HTTP/HTTP2 and uses Windows platform crypto for its host operations. The curl notice also retains the complete ISC notices from compiled inet_ntop.c/inet_pton.c. The nghttp2 notice retains the complete sfparse MIT notice, including sfparse/nghttp3/nghttp2 contributor copyrights and both Bjoern Hoehrmann UTF-8 DFA copyright lines with their complete MIT notice. The window shows the catalogue in About, one entry per component.

macOS curl and Apple frameworks are system-linked libraries, rather than products embedded in Voyemu. macOS also links the system libarchive through the pinned libarchive 3.8.9 headers; the catalogue embeds `libarchive.txt`, byte-identical to that release `COPYING` and checked against the dependency lock SHA256, and the installed notice set keeps the same copy. QEMU, Android SDK tools and JDK are separately prepared runtime/toolchain products, and are deliberately excluded from this executable-embedded catalogue.

The QNX boot stream unpacks with lzokay (MIT, Jack Andersen 2018), compiled statically into Voyemu on every host from the commit pinned in `src/app/dependencies.lock.json`; `lzokay.txt` is byte-identical to its `LICENSE` and checked against that pin. Voyemu uses only its decompressor, which follows the LZO1X format description in the Linux kernel documentation; the packer in `src/app/qnx/qnx_lzo_pack.cpp` is Voyemu's own code written from the same description. Together they replace the GPL-2.0-or-later liblzo2 shared library.

ZIP archives, and on Linux PNG captures, are read and written with miniz (MIT), compiled statically into Voyemu on every host from the release pinned in `src/app/dependencies.lock.json`; the catalogue embeds its `LICENSE` from that verified download with LF line ends. The embedded ADB builds on Android Open Source Project sources under the Apache License 2.0, kept in `src/app/third_party/aosp_adb/` with their notice in `NOTICES.txt`.

The `Runtime` install component copies every notice of the catalogue into `notices/`, together with `dependencies.lock.json`.

## Downloaded guest libraries

The Free A11 7.3.1 profile downloads player-ijk 3.3.7 and FFmpegMediaMetadataRetriever-native-arm64-v8a 1.0.16 from Maven Central; their archive URLs, SHA256 values and ten selected ARM64 library hashes are pinned in `profiles/free-11-chinese-20260731-7.3.1/components/gallery-arm64-libraries/component.json`. Preparation adds those libraries to the owner-provided Gallery APK. They are not linked into the Voyemu host executable and are not included in the source-only distribution or its embedded host license catalogue.

The Maven POM Apache-2.0 declarations do not describe all native dependencies: the payload includes IJK/FFmpeg and OpenSSL. The component keeps `distributionLegalClosure: false`: exact corresponding source and complete notices for redistribution of these selected native binaries have not been established. Publishing Voyemu source and profile download recipes does not authorize redistribution of a prepared OEM machine. Distribute a prepared machine only after separately establishing the permissions and source/notice obligations for both OEM materials and all included libraries.
